FlyRank ML Internship • Week 8 Capstone

Content Refresh Opportunity Scoring

Ranking content items for potential editorial and SEO review using historical content-performance signals.

Abstract

Content teams often have more pages that could be reviewed than they have capacity to refresh, making prioritization difficult. This project investigates whether historical content-performance signals can be used to rank which content items should be prioritized for refresh or review.

A Random Forest model was trained using historical visibility, engagement, search-position, and content-freshness signals and compared with a simple visibility-and-staleness baseline.

On a client-level held-out evaluation split, the Random Forest achieved a Precision@50 of 80%, compared with 52% for the baseline.

This represents a measured improvement of 28 percentage points in Precision@50.

The result suggests that machine-learning ranking can provide useful decision support for prioritizing content review, while the model should not be interpreted as evidence that refreshing a page will causally improve its future search performance.

1. Introduction / Problem Statement

SEO and editorial teams may have many content items that could potentially be reviewed or refreshed. Because available editorial capacity is limited, reviewing every content item equally is inefficient.

This project focuses on creating a repeatable ranking system that identifies content items showing historical patterns that make them appropriate candidates for editorial or SEO review.

Research Question

Can historical content-performance signals be used to rank which content items should be prioritized for refresh or review?

Decision Supported

Prioritize content items for editorial or SEO review when refresh capacity is limited.

Scope: This project is a decision-support ranking system. It does not attempt to explain Google's ranking algorithm and does not claim that refreshing recommended content will cause improved search performance.

Target Definition

A proxy refresh target was created using:

target_refresh = trend_pct < -10

A value of 1 indicates that the observed trend percentage is below -10%. This is a proxy label and does not directly measure whether refreshing a content item would improve future performance.

Model Features

The final Random Forest model uses ten performance and freshness features:

  • impressions_90d
  • clicks_90d
  • ctr
  • avg_position
  • sessions_90d
  • pageviews_90d
  • users_90d
  • engaged_sessions_90d
  • engagement_rate
  • days_since_last_update

The fields trend_pct, client_id, and content_id were excluded from the model features.

Baseline

The Week-4 baseline combines visibility and content staleness:

Baseline Score = 0.70 × Visibility Score + 0.30 × Staleness Score

Visibility is based on the percentile rank of impressions_90d, while staleness is based on the percentile rank of days_since_last_update.

Random Forest Model

The final model is a Random Forest classifier with 300 trees, maximum depth of 10, minimum leaf size of 10, balanced class weighting, and a fixed random seed of 42. Missing numeric values were handled using median imputation.

Validation Design

The model was evaluated using a client-level 80/20 grouped split. The training set contained 23,837 rows across 25 clients, while the test set contained 6,163 rows across 7 clients.

No client was shared between the training and test sets.

Evaluation Metric

The primary metric is Precision@50. It measures the proportion of the top 50 ranked recommendations that match the proxy refresh target.

Leakage Checks

  • trend_pct was not used as a model feature.
  • Client identifiers were excluded.
  • Content identifiers were excluded.
  • Training and testing clients did not overlap.
  • Future observations were not intentionally used as inputs.
  • Missing-value preprocessing was based on training data.

5. Limitations & Honest Framing

Proxy Target

The label trend_pct < -10 identifies an observed decline pattern. It does not directly measure whether refreshing a content item would improve its future performance.

Directional Result

The Random Forest achieved 80% Precision@50 on the held-out client evaluation, but this should not be treated as a guaranteed production performance level.

Google's Ranking Algorithm

The model does not explain Google's ranking algorithm. The features represent observed content and search-performance patterns and do not prove that any individual feature is a Google ranking factor.

No Causal Inference

The model identifies content associated with the proxy target. It does not prove that taking a recommended action will cause traffic, clicks, rankings, or engagement to increase.

Dataset Coverage

The available data has differences in data availability across sources and time periods, and this analysis uses a limited reporting window.

Group-Based Evaluation

The client-level split provides separation between training and testing, but the evaluation still represents a finite set of pseudonymized clients. Further validation would be appropriate before operational use.

Appropriate interpretation: The model is a prioritization and decision-support tool for identifying content worth reviewing, not an automated guarantee of SEO outcomes.

6. Ranked Recommendations

Each recommendation contains a refresh score, model probability, confidence level, reason codes, and suggested action. These fields help an editorial or SEO team understand which content items should receive attention first and why.

Action Playbook

1. Prioritize high-scoring content

Start editorial review with the highest-ranked content items.

2. Review the reason codes

Use reason codes to understand the signals behind each recommendation.

3. Consider visibility and performance together

High-visibility content with concerning performance patterns can represent a useful review opportunity.

4. Consider content freshness

Evaluate content staleness together with recent performance signals rather than using freshness alone.

5. Keep humans in the loop

Treat the model output as a review signal rather than an automatic instruction to refresh content.

Performance Signals → Model Score → Ranked Queue → Reason Codes → Human Review → Editorial Decision

9. Conclusion

This project demonstrates that historical content-performance signals can be used to create a repeatable ranking system for content review prioritization.

The Random Forest achieved 80% Precision@50 compared with 52% for the Week-4 baseline, resulting in a measured improvement of 28 percentage points on the held-out client evaluation.

The system converts model output into a practical ranked queue containing scores, confidence levels, reason codes, and suggested actions.

However, the model should be treated as decision support rather than a causal prediction of refresh success or search-engine ranking changes.

Future work could incorporate verified refresh outcomes and future-window labels to evaluate whether prioritized recommendations translate into measurable improvements.
