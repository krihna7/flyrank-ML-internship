Abstract

Content teams often have more pages that could be reviewed than they have capacity to refresh, making prioritization difficult. This project investigates whether historical content-performance signals can be used to rank which content items should be prioritized for refresh or review.

A Random Forest model was trained using historical visibility, engagement, search-position, and content-freshness signals and compared with a simple visibility-and-staleness baseline.

On a client-level held-out evaluation split, the Random Forest achieved a Precision@50 of 80%, compared with 52% for the baseline.

This represents a measured improvement of 28 percentage points in Precision@50.

The result suggests that machine-learning ranking can provide useful decision support for prioritizing content review, while the model should not be interpreted as evidence that refreshing a page will causally improve its future search performance.

Introduction / Problem Statement

SEO and editorial teams may have many content items that could potentially be reviewed or refreshed. Because available editorial capacity is limited, reviewing every content item equally is inefficient.

This project focuses on creating a repeatable ranking system that identifies content items showing historical patterns that make them appropriate candidates for editorial or SEO review.

Research Question

Can historical content-performance signals be used to rank which content items should be prioritized for refresh or review?

Decision Supported

Prioritize content items for editorial or SEO review when refresh capacity is limited.

Scope: This project is a decision-support ranking system. It does not attempt to explain Google's ranking algorithm and does not claim that refreshing recommended content will cause improved search performance.

Proxy Target

The target variable was constructed from the observed trend signal:

Target Definition

target_refresh = trend_pct < -10

This target represents a proxy for observed decline. It does not directly measure whether a content refresh would produce a positive future outcome.

Final Model Features

Baseline

The baseline combines historical visibility and content staleness:

Baseline Score = 0.70 × Visibility Score + 0.30 × Staleness Score

Visibility is based on the percentile rank of impressions_90d, while staleness is based on the percentile rank of days_since_last_update.

Random Forest Model

The final model is a Random Forest classifier with 300 trees, maximum depth of 10, minimum leaf size of 10, balanced class weighting, and a fixed random seed of 42.

Missing numeric values were handled using median imputation.

Validation Design

A client-level 80/20 grouped split was used for evaluation. The training set contained 23,837 rows across 25 clients, while the test set contained 6,163 rows across 7 clients.

No client was shared between the training and test sets.

Evaluation Metric

The primary metric is Precision@50. It measures the proportion of the top 50 ranked recommendations that match the proxy refresh target.

Leakage Checks

  • trend_pct was excluded from model features.
  • client_id was excluded.
  • content_id was excluded.
  • Training and testing clients were separated.
  • Preprocessing was performed without using test information.

Limitations & Honest Framing

Proxy Target

The target trend_pct < -10 represents an observed decline pattern rather than a direct measurement of successful content refresh.

No Causal Claim

The model identifies content associated with the proxy target. It does not prove that refreshing a recommended page will cause rankings, traffic, clicks, or engagement to increase.

Search Algorithm Interpretation

The features used in this project should not be interpreted as proven Google ranking factors. The model studies associations within the available content-performance data.

Generalization

The evaluation uses a finite set of pseudonymized clients. Additional validation on future data and additional clients would be appropriate before operational use.

Honest framing: This system should be treated as a prioritization and decision-support tool, not as a guarantee of SEO outcomes.

Ranked Recommendations

The final system produces a ranked queue of 200 content recommendations.

Each recommendation can be used to prioritize editorial or SEO review based on the model score, confidence, reason codes, and associated performance signals.

1. Prioritize high-scoring content

Begin review with the highest-ranked content items when editorial capacity is limited.

2. Review the reason codes

Use the generated reason codes to understand the signals contributing to each recommendation.

3. Combine visibility and freshness

Consider content visibility together with performance and freshness rather than relying on a single signal.

4. Keep human review in the loop

The ranking should guide editorial investigation rather than automatically trigger content changes.

5. Monitor outcomes

Future work should evaluate whether recommendations correspond to meaningful outcomes after editorial actions are taken.

Model Score → Ranked Queue → Reason Codes → Human Review → Editorial Decision

Conclusion

This project demonstrates how historical content-performance signals can be used to build a repeatable ranking system for content review prioritization.

The Random Forest achieved 80% Precision@50, compared with 52% for the baseline, producing a measured improvement of 28 percentage points on the held-out client evaluation.

The resulting system converts model predictions into a ranked queue that can help editorial and SEO teams decide which content items deserve attention first.

The model is intended as decision support. It does not establish causality, explain Google's ranking algorithm, or guarantee that refreshing a recommended page will improve future performance.
